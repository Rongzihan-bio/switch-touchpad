# Touchpad Diag 0.3.4

独立的启动诊断程序，不依赖 Touchpad 后台，不修改 Atmosphere 设置，不创建 boot2.flag。当前仅通过编译和文件结构检查，尚未真机验证。

## 安装和操作

Touchpad rc10 主安装包已包含 `switch/touchpad-diag/touchpad-diag.nro`。独立 Diag 包另含 `atmosphere/contents/4200000054505052/exefs.nsp`，这是保留在 System 池的旧极小探针，没有 `boot2.flag`。按包中相同路径合并到 SD 卡，现有 Touchpad 模块保持手动启动模式。

通过应用模式／全内存 hbmenu 打开 **Touchpad Diag**，避免相册 applet 模式。界面使用英文，便于默认控制台字体显示：

- 打开后自动采集只读信息；等待顶部显示 READY。
- **A**：rc10 首测使用此键，本次运行只允许一次后台启动测试。已有后台进程或命名端口时跳过；日志不可写、诊断不在应用模式、旧探针仍运行时不启动。测试启动的是卡上的现有后台，仍可能触发它自身的错误。
- **B**：历史对照用，本轮 rc10 不需要。启动旧的极小 System 池进程，不初始化服务、HID、显示或 SD；成功后空闲至重启。它与 rc10 的池和资源组不同，不能代表新版后台。Touchpad 已运行时跳过。主安装包没有附带该探针，需使用既有安装或独立 Diag 包。
- **X**：重新采集只读信息，不启动后台。
- **上／下方向键**：查看报告页；完整长行保存在日志文件中。屏幕最多保留最近 1024 行。
- **+**：READY 状态下退出。不自动终止后台，不启用虚拟手柄。

顶部 `Launch` 显示实际调用返回码；跳过或阻止时明确显示 `NOT LAUNCHED`，不附零返回码。顶部另显示 APPLICATION 或 APPLET 模式；`Last stage` 显示最近阶段。0.3.0 在跳过提示后附零码容易被误读，已于 0.3.1 修正。

服务请求在工作线程执行，画面持续显示。同步系统服务没有在此实现强制取消：若长期停留在 CALL IN PROGRESS，请记录当前页面；日志最后一个 STAGE 可用于定位调用阶段。退出仍需等待正在执行的服务请求返回。

## 日志

每次运行创建独立文件：`sdmc:/config/touchpad/diagnostics/diag-<tick>-<序号>.log`。

通过 USB 文件传输或 SD 卡读回整个日志文件。文件名中的 tick 不表示日历时间。每行刷新、阶段同步写入；写入或同步失败会显示日志不可用。

记录内容：

- HOS 版本、运行模式、Atmosphere 检测标志。精确 AMS 版本仍需单独记录，不能从 HOS 推断。
- Touchpad 后台和 overlay 文件大小、修改时间及 SHA-256，是否存在开机标记。
- 在 hbloader 的 SVC 可用性提示允许时，读取进程列表、PID 对应的程序编号、物理内存池及诊断程序自身资源组额度。调用失败记录原始错误码；没有提示则跳过。
- 通过 Atmosphère pm:dmnt 65001，读取 System（group=0）及 Applet（group=2）共享资源组的五类实际额度，记录 used、limit、available。输入索引在代码中限定；不调用调额或内存扩容接口。调用失败即停止后续组额度查询，保留错误码。
- 后台进程是否存在、命名端口能否连接。不发送可能等待后台响应的诊断 IPC。
- 探针和 Touchpad 分别记录服务连接、LaunchProgram 返回码及返回 PID；启动后立即和约 2 秒后观察，无自动重试。
- 既有 startup.log 与启动后的内容。旧日志可能过期；内容没变不能证明没有执行。端口出现不等于触摸链路可用。

## 数据含义和限制

`SELF` 属于 **诊断程序自身的资源组**；`POOL` 是物理池统计；`PM Applet` 才是 rc10 配置所属的资源组统计，`PM System` 为旧后台与探针对照。组内其他进程也会改变用量，前后差额不一定全是 Touchpad。0.2.0 的旧日志没有 PM 组额度，不能从旧日志得出精确缩堆目标。接口依据见 [内存需求核查](MEMORY_RESEARCH.md)。

`00010801` 只确定 LimitReached，不能区分内存、线程等具体受限资源。即使 LaunchProgram 成功，仍须结合 PID、命名端口和初始化日志判断后续阶段。探针成功仅证明当时能启动一个极小的 System 池进程，不能证明 rc10 的 Applet 配置、初始化或运行时功能可用。

诊断程序增加一个工作线程和控制台，堆大小请求为 16 MiB，但 hbloader 可能提供自身的堆覆盖值。它会改变资源基线；不能把应用模式诊断结果直接等同于桌面 Tesla 启动条件。相册 applet 模式会占用本轮要测试的池，因此 0.3.1 在该模式下仅收集，阻止 A 启动测试。

日志包含程序编号（可能反映运行的软件），不采集账号、密钥、存档或游戏内存。当前 Switch MCP 只能读屏和控制按键，不能读取日志文件；完整报告需另外传回。

## 构建

运行 `python3 scripts/build.py` 后执行 `python3 scripts/package_diagnostic.py`。独立安装包只含诊断 NRO、极小探针后台和说明／许可证，不替换 Touchpad 后台与 Tesla 插件。探针目录没有 boot2.flag，进程只由 B 键手动启动。配套源码包保留本仓库完整构建依赖；此版本通过交叉编译与结构检查，不将这些检查表述为真机测试。
