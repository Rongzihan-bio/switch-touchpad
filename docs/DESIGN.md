# 首版实现约定

本文件记录用户在 2026-09-22 多轮确认后的首版范围；比原始 `Agent.md` 中的完整手柄目标更小，并明确启用了 ABXY 滑动切换。

## 进程与数据流

Tesla `.ovl` → 固定长度 CMIF 请求 → 后台命名端口 `touchpad`。

后台内部分为输入采样与映射、HDLS 发送、VI 绘制及控制 IPC 四条执行路径。实时状态只在进程内受互斥锁保护的内存中流动，服务调用和磁盘保存均不持有该锁。绘制阻塞不会阻塞正常运行的输入发送线程。

使用内核命名端口，是为了后台不存在时连接立即报错，避免服务管理器的等待语义让设置界面一直阻塞。最多四个客户端会话；仅接受固定长度、无句柄、无缓冲区描述符的非 domain 请求，并支持 libnx 建立会话所需的 pointer-buffer-size 查询。

## 协议 v1

定义见 `common/protocol.hpp`，`Request` 为 40 字节、`Status` 为 120 字节，均用固定宽度整数和编译期尺寸断言。

| 命令 | 行为 |
|---|---|
| Status | 返回模式、设置、输入、连接／显示状态、HOS 和错误码 |
| Configure | 校验并保存三项设置；先停止输入，再更新配置 |
| Prepare | 为当前运行应用准备一次启用，返回 token，5 秒失效 |
| Commit | 必须携带当前 token；进入等待所有触点抬起的阶段 |
| Stop | 清零并要求断开虚拟手柄 |
| Pause | 活动状态清零；保留中立连接及已有停止原因 |
| PreparePair | 准备一次系统配对；不要求存在运行游戏 |

除 `Status` 外的修改操作都不传递任意游戏输入。游戏输入仅从本机触摸映射产生；L＋R 只由主动配对命令产生一次约 400 ms 脉冲。

## 输入规则

- 基准画布为 1280×720；摇杆中心 `(180,540)`、半径 100。按钮组锚点 `(1100,540)`，四个中心距锚点 75，按钮半径 36。缩放不改变两组锚点。
- 摇杆仅在新触点落入区域时捕获，以 `finger_id` 跟踪，不依赖数组顺序。已有第二个手指不能在第一个离开后突然接管摇杆。
- 摇杆采用径向死区、死区外幅度重映射和圆形限幅；屏幕向上映射到手柄 Y 正方向。
- 未被摇杆捕获的触点根据当前位置命中 ABXY；同一按钮的有效触点做逻辑或。支持最多 16 个触点。
- 拒绝重复触点标识、非法坐标及非法数量。触点丢失释放，显式 End 触点不继续映射。
- 触摸采样以约 60 Hz 为目标；HDLS 发送线程约每 8 ms 检查一次最新完整快照和生产者心跳。

## 生命周期与边界

准备／等待阶段上限为 5 秒。进入菜单、HOME／电源按钮、游戏 PID 变化、底座模式、触摸采样停滞、采样线程心跳超时或时钟间断都会停止输入并使旧 token 失效。触摸及采样线程超时阈值为 250 ms；发送线程重新获得调度时先检查心跳与独立时钟观察值。

后台读取 HOME／电源共享内存，不获取或清除 AM 使用的事件句柄。Tesla 组合键从它的配置文件读取，在打开本插件或准备启用时重新加载。自家插件额外在显示时发送 Pause。

`pmdmntGetApplicationProcessId()` 只用于识别运行应用及应用切换，**不是前台焦点证明**。因此 UI 要求只在游戏画面启用；不宣称能识别所有系统弹窗。短暂休眠、所有自动休眠路径及第三方加载器焦点差异仍需真机测试。没有冒用系统 PSC 模块 ID 注册电源模块。

采样心跳检查只在发送线程仍在运行时有效。rc10 不再因绘图心跳过期停止输入；绘图只提供反馈，实际绘图接口失败仍停止输入。HDLS 服务阻塞、整个进程崩溃或系统挂起时不能依赖进程内 watchdog。断开失败时保留句柄并继续尝试中立／断开，不静默创建第二个设备。

## 显示与权限

独立 VI managed layer、RGBA4444、640×360 双缓冲，由 VI 放大至屏幕；触摸逻辑保持 1280×720；先在线性缓冲绘图，再按 Tegra 16Bx2 排列写入显示缓冲。仅 Active 状态加入 Default／LCD 栈；Off／Paused 移出栈且不提交透明空白帧。菜单 Pause 回复需确认移除完成，设置层隐藏也移出自己的显示栈。Z 顺序设在 Tesla 顶层下方。

rc7 后台使用 Applet 物理内存池（NPDM pool_partition=1）和 Applet PM 资源组（application_type=2），固定堆为 4 MiB、主线程栈为 64 KiB。libnx __nx_applet_type 仍为 AppletType_None，不建立 AM 小程序会话、不请求前台焦点。显示缓冲、线性画布、NV transfer memory、工作线程栈及服务配置均从固定堆分配，双缓冲下已知至少占 1,758 KiB；rc5 的 1.25 MiB 堆缺少余量，详见 [内存需求核查](MEMORY_RESEARCH.md)。Applet 池和资源额度由多个进程共享；启动、图形服务、系统小程序共存及实际峰值仍待实机测量。

NPDM 程序编号为 `4200000054504144`，CPU 3，服务权限使用明确列表，文件系统权限仅申请 SD 卡 (`0x200000`)。不引入 HID MITM、不屏蔽原生触摸、不修改实体控制器映射。

设置文件采用“写入并 flush 临时文件 → 保留旧文件为 `.bak` → 提升新文件”的恢复流程，避免假设 Horizon RenameFile 可以覆盖已有目标。启动优先读取有效主文件，其次备份，否则使用默认值。

rc7 的 Tesla 通信使用带 1 秒等待上限的异步 IPC，仅适用于具有事件额度的 System/Tesla 进程。超时请求页保留至内核完成，不重发、完成前不卸载 overlay。常规 NRO 客户端仍为同步 IPC；输入测试初始化后释放 SM 的直接连接名额。界面输入回调不持有轮询锁，退出先恢复输入再清屏；详见 [rc7 运行修正](RUNTIME_RC7.md)。

rc8 的菜单／按键层切换与实机证据见 [RUNTIME_RC8.md](RUNTIME_RC8.md)。

rc9 的心跳检查在运行状态锁内取得当前时刻，避免跨 IPC 的旧时间与新心跳比较；自动停用先释放输入再记录原因。见 [RUNTIME_RC9.md](RUNTIME_RC9.md)。

rc10 按用户要求允许显示延迟，只要采样正常便继续发送输入。绘图线程恢复后记录 `render-delay-ms`，最频繁每 5 秒一次，避免让正常输入发送线程等待 SD 写入；见 [RUNTIME_RC10.md](RUNTIME_RC10.md)。
