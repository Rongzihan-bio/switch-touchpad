# Touchpad 0.1.1-rc7：输入恢复与运行诊断修正版

## 读取的实机证据

2026-09-24，从用户 SD 读取并核对四个安装文件，均与 rc6 发布产物一致。`startup.log` 记录 HID、HDLS 和工作线程初始化均成功；Diag 日志查到后台 PID 136，命名端口可连接。没有发现同次故障新增的 Atmosphère crash_reports。

这份 Diag 日志的实际模式为 `appletType=2`（相册 Applet），A 测试被阻止，并未执行 LaunchProgram。旧版界面给“阻止／跳过”也附上零返回码，存在误导。后台已运行的证据来自 PID、端口和初始化日志。

System PM 内存剩余 802,816 字节，Applet 剩余 144,056,320 字节；与之前的 System 内存限制相符。本轮不再缩堆，保留 Applet 池和资源组、4 MiB 堆。

原始证据及安装二进制保存在本机 `build/deployment/rc6-runtime-evidence-20260924/`。用户明确确认异常发生于点击“启动后台（本次开机）”；HOME 能响应、Tesla 组合键不响应。旧版没有按钮／焦点日志，不能确定该次具体阻塞位置。

## 修正

- Tesla 按钮回调不再持有输入轮询线程的 mutex；系统调用等待时，轮询不再同时被这把锁阻塞。
- Tesla 对 Touchpad 的通信改用异步 IPC，界面最多等待 1 秒。超时后不重发；内核仍持有的请求页和事件保留至完成，在完成前禁止卸载当前 overlay，避免释放仍被使用的内存。用户可按 HOME 或组合键隐藏。此超时仅覆盖 Touchpad IPC，不宣称系统 PM／HID／VI 服务都有超时。
- 后台已连接时点击启动只显示“后台已运行”；连接状态未知时，再用 PM 查询 PID，存在就不重启。未知查询错误也不当作“未运行”。
- 退出菜单先恢复系统／应用输入权限，再进行最后清屏；检查恢复结果，失败时不提交启用命令。PID 查询失败不会沿用上次 PID。
- 轮询线程在事件、界面创建后才启动，退出时先回收线程再释放事件；隐藏请求通过原子标志交给界面线程处理，避免跨线程改动画状态。拒绝卸载时保留 GUI。
- 通信失败时显示层和后台错误码显示“未知／无法读取”，不继续显示上一次成功数据。“虚拟手柄未连接”改为“未启用时不连接”。
- 后台恢复 640×360 双缓冲，避免唯一画面缓冲被显示端持有时没有备用缓冲。libnx 支持单缓冲，因此这不是已证实的唯一根因。增加的 480 KiB 在已有 4 MiB 堆内分配，已知基础分配至少 1,758 KiB。
- 输入测试程序初始化后释放暂不需要的 SM 连接，为 Application 组通常仅 1 个直接连接名额腾出位置；普通客户端不再做多余的指针缓冲查询或同步关闭握手。
- Diag 0.3.1 对未执行的启动明确显示 `NOT LAUNCHED`，不再附零返回码；诊断和输入测试界面都显示 APPLICATION／APPLET 模式。

增加 `config/touchpad/overlay.log`、`runtime.log` 记录按钮、焦点恢复、后台命令、HDLS 连接和画面显隐转换；各保留一份 `.previous.log`。仅记录转换，未记录每帧触摸内容。原有 startup.log 和独立诊断日志继续保留。

## 本轮操作

1. 完整重启主机。按住实体手柄 **R** 启动一款已安装的游戏，持续按住到 hbmenu 出现；打开 **Touchpad Input Test**，确认顶部为 **Mode: APPLICATION**。普通打开相册不算这个模式。
2. 用原有 **ZL + ZR + 方向下** 呼出 Tesla，打开 Touchpad，确认标题为 **0.1.1-rc7**。
3. 本次开机未启动后台时，选择“启动后台（本次开机）”。此项应保留菜单，等待显示层就绪；若已运行，无需再次启动。
4. 选择“启用并返回游戏”，菜单收起后先抬起所有手指。观察是否出现左摇杆与 ABXY，以及测试程序实际收到的按钮／摇杆变化。
5. 呼出 Tesla 或按 HOME，应暂停控制并能继续使用实体手柄。回来需要手动启用。

如仍异常，不需反复触发；通过 HOME 正常关机后读回 `config/touchpad` 中的日志。请同时记录当时点击的按钮和屏幕提示。

## 验证边界

交叉编译和产物结构检查；电脑端触摸／设置／绘图测试；模拟传输测试覆盖无响应、迟到回复、缓冲保留、禁止重发、协议不匹配和事件额度失败。模拟测试不替代 Switch 内核异步 IPC、显示与焦点共存的实机验证。完整实机问题尚不能宣布解决。
