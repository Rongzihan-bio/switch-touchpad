# Touchpad 0.1.1-rc8：显示层切换验证版

## rc7 实机证据

2026-09-24 读取 SD，四个安装文件的 SHA-256 均匹配 rc7 发布产物。完整日志保存在本机 `build/deployment/rc7-failure-evidence-20260924-133825/`；没有找到本轮新增的 Atmosphère 崩溃报告。

同一次开机的单调时钟时间线：

| 时间（毫秒） | 日志事实 |
|---|---|
| 179723 | 用户点击 `button-start-backend` |
| 179852 | `pm-launch-end` 返回 0，PID 140 |
| 180027–180049 | 后台双缓冲初始化、第一张透明画面提交均成功 |
| 185119 | 菜单才收到隐藏请求，距离启动返回约 5.27 秒 |
| 185208–185225 | 恢复输入、清屏、隐藏回调均返回成功 |
| 231363–231418 | 菜单再次执行显示，Pause 请求得到后台回复 |
| 233590–233631 | 又一次执行菜单显示，Pause 再次成功 |

后台收到的非状态命令全部是 Pause（5），模式一直为 Off（0）。没有启用、Commit 或虚拟设备连接日志。因此这次没有进入虚拟手柄注入阶段，也没有证据支持 LaunchProgram 卡死或 Tesla 主线程一直停住。

用户实际看到的是菜单消失、应用暂时不收手柄输入，触屏后恢复输入、仍看不见 Tesla。结合上面的显示／隐藏回调，**优先假设菜单仍在运行但无法呈现在屏幕上**：看不见的菜单仍可能持有输入焦点，触到菜单外区域后触发隐藏、恢复应用输入。rc7 没有记录隐藏原因、VI 层 ID、Z 值，因此不能证明该假设、具体硬件合成层数量或唯一根因。

## rc8 改动

- 后台初始化 VI、窗口和双缓冲资源后，Off 状态不加入 Default／LCD 栈，也不提交透明空白画面。`显示层：已就绪` 表示资源已准备，不代表当前出现在屏幕。
- 仅 Active 状态将按键层加入屏幕；退出 Active 时移出栈。重新加入后才取下一块缓冲，避免已隐藏的显示消费者不释放旧缓冲；停止与取缓冲竞态时取消该缓冲。
- Touchpad 自己的 Tesla 设置层也只在菜单打开期间加入显示栈，隐藏时移出，不再靠保留一张透明画面实现隐藏。此修改只编译在 touchpad.ovl 内。
- 再次显示菜单时，先发送 Pause。后台使用请求代次确认渲染线程已经处理移除，最多等待 400 ms，之后返回失败；未确认移除时不接管应用输入。旧帧不能确认较新的请求。整个 Touchpad IPC 仍使用 rc7 的 1 秒超时和缓冲保留机制。
- 关闭菜单先恢复应用输入，再移除设置层；移除失败时取消待提交的启用命令。
- 日志增加菜单隐藏原因位图（API=1、组合键=2、HOME=4、电源=8、菜单外触摸=16）、两个 VI 层的 ID／Z、加入／移出栈结果和 Pause 移除确认。
- 保留已能启动的 Applet 池／资源组、4 MiB 堆、双缓冲、手动启动方式；Diag 版本为 0.3.2。

VI managed layer、Z 设置依据 [libnx 4.12.0 vi.c](https://github.com/switchbrew/libnx/blob/v4.12.0/nx/source/services/vi.c)。加入／移出栈为 IManagerDisplayService 6000／6001，见 [Switchbrew 显示接口](https://switchbrew.org/wiki/Display_services#IManagerDisplayService)。原版 libtesla 的菜单层初始化与透明清屏见 [固定提交源码](https://github.com/WerWolv/libtesla/blob/f766e9b607a05e9756843cbd62b3bfb98be1646c/include/tesla.hpp)。这些资料支持接口与生命周期分析，不能代替目标主机的显示行为测试。

## 两步验证

1. 完整重启；按住 R 启动游戏进入 hbmenu，运行 Touchpad Input Test，确认 `Mode: APPLICATION`。通过原有 ZL + ZR + 方向下打开 Touchpad，确认 rc8。只点一次“启动后台（本次开机）”，应仍看见菜单且能用手柄上下移动；然后隐藏、重新呼出一次菜单。
2. 仅第一步正常后，选择“启用并返回游戏”，抬起所有手指，再测试触摸左摇杆、ABXY，以及 HOME／Tesla 暂停与恢复。

第一步再次出现不可见菜单时，不要盲点“启用”，通过 HOME 退出并正常关机，读回 config/touchpad 日志。rc8 保留一份上一轮日志。

## 验证边界

电脑端触摸与协议测试、模拟异步传输测试、模拟显示栈切换测试均不能确认实际 VI 是否按预期显示；交叉编译及 NPDM／NRO／NSO 检查也不代表实机通过。rc8 是依据新证据实施的候选修正，完整触摸输入链路仍未在用户主机验收。

## 后续实机反馈

用户确认 rc8 显示及游戏触摸输入可用；出现数秒后自动停用，继续调查和 rc9 修正见 [RUNTIME_RC9.md](RUNTIME_RC9.md)。
