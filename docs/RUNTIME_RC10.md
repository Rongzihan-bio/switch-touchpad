# Touchpad 0.1.1-rc10：加载时允许绘图延迟

## 故障证据

rc9 的三次实机停止记录均为 `watchdog-stop-reason detail=10`，当时采样心跳年龄分别为 47、70、117 ms，绘图心跳年龄为 254、250、256 ms。后台随后移除显示层，进程仍能响应菜单。这些消失由代码中的绘图 250 ms 阈值触发，不能据此归因为内存不足或系统杀进程。详细日志和局限见 [RC9_LOAD_FAILURE.md](RC9_LOAD_FAILURE.md)。

## 本版行为

用户选择“采样正常就继续输入，允许画面反馈延迟”。因此 rc10 删除绘图心跳过期触发的停止分支，保持触摸采样、手柄发送与绘图线程独立。

- 游戏加载造成绘图迟延时，采样正常便继续更新按键和摇杆，包括松手释放。控件不因这条超时规则主动移除；实际屏幕合成仍由系统决定。
- 显示恢复后绘制最新输入状态，无需重新启用，也不增加一次抬手等待。最初主动启用时的抬手规则保持不变。
- 触摸样本不更新或采样线程停滞达到 250 ms、时钟间断、HOME／Sleep／Tesla、游戏切换、底座模式和非法输入仍停止输入。
- 实际显示接口失败和 HDLS 错误继续进入停止或故障状态。取消心跳超时不等于忽略接口返回错误；若所有线程都失去调度，不能保证输入继续发送。
- 绘图恢复后，`runtime.log` 可记录 `render-delay-ms detail=<间隔>`，最频繁每 5 秒一次，由绘图线程写入。该记录是两次绘图循环心跳的间隔，不能单独定位 GPU、服务等待或 CPU 原因；输入发送线程不为此新增磁盘写入。

保留 Applet 物理池／PM Applet 资源组、4 MiB 固定堆、64 KiB 主栈、640×360 双缓冲及 rc8 显示栈切换。协议仍为 v1，结构尺寸不变，后台仍手动启动。本版没有调高内存额度。

## 验证范围

回归测试重放三组实机心跳年龄；模拟绘图心跳冻结 24 秒，同时反复按住及释放 A 和左摇杆，验证状态机保持活动、输入仍随采样更新。显示恢复无需新 token。另覆盖真实 250 ms 采样停滞和实际显示错误后的中立状态，以及暂停后不自行重启输入。

保留 rc9 的旧时间竞态和 120 秒模拟持续输入测试，执行原有核心、通信、显示栈测试。模拟时间与主机测试均不代表 Switch 持续运行成绩；HDLS 与实际画面效果仍需下述实机验证。

使用固定版本离线工具链的交叉编译及结构检查通过，后台镜像加主栈为 5,058,560 字节（4.8242 MiB）。

## 安装后验证

1. 完整重启，打开 Tesla → Touchpad，确认标题是 **0.1.1-rc10 · 加载兼容修正版**。
2. 进入之前触发故障的游戏，点击“启动后台（本次开机）”，然后“启用并返回游戏”，抬起全部手指后开始操作。
3. 重复同一段重负载加载，检查加载前后控件和输入；画面反馈延迟允许存在，松手后输入应随采样释放。
4. 检查 HOME／Tesla 停用仍有效。若再次消失，记下菜单底部原因；即使没有记下，保留 SD 日志仍可继续分析。

启动时会写 `rc10-backend-start`、`rc10-overlay-start`，用于区分运行的新旧程序。必须重启才能替换已经驻留内存的旧后台。rc9 另一个较晚发生的 `001C24CA` 控制器接口错误仍未定位，本版不宣称已修复。
