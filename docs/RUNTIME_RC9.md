# Touchpad 0.1.1-rc9：心跳计时竞态修正版

## rc8 实机进展和日志

用户确认 rc8 能正常启动，在游戏内显示虚拟控件并识别触摸按键，但启用后数秒消失，重新启用可恢复。

2026-09-24 读取的 SD 文件与 rc8 安装摘要一致。日志已保存在本机 `build/deployment/rc8-stop-evidence-20260924-140119/`。单次后台启动后，出现多次 Commit、显示层加入和移除；移除后相同后台继续回复 Pause／Prepare／Commit，没有新的后台启动记录。例如：

- 110192 ms 完成首帧，121109 ms 移除显示层，持续约 10.9 秒；125444 ms 后台继续处理 Pause。
- 127299 ms 完成首帧，132385 ms 移除显示层，持续约 5.1 秒；随后可再次 Prepare／Commit。
- 149975 ms 完成首帧，161561 ms 移除显示层，持续约 11.6 秒。

这些记录说明前几次发生的是活动功能停用，后台没有被系统终止；不能把最后一段日志以后的进程状态视为已知。rc8 没有记录自动停用原因，不能仅从这些时间确认每一次的具体触发分支。

## 确定的代码缺陷

发送线程原先先执行 `nowMs()`，随后调用时间服务 IPC，最后取得运行状态锁，读取采样／显示线程的心跳。其他线程可在 IPC 等待期间更新心跳，于是出现：

```text
发送线程旧时间 = 1000 ms
系统服务等待期间，采样／显示线程发布心跳 = 1008 ms
发送线程拿旧时间比较新心跳：1000 < 1008
误判为超时或绘图异常，调用 stop()
```

这是真实的跨线程时间快照竞态，电脑端已用受控时序复现旧判断。它能解释非固定几秒后停止、随后重新启用的表现，但旧日志没有原因字段，因此尚不能宣称是所有本次停用的唯一原因。

## 修正

- 时间服务调用结束后，在运行状态锁内读取心跳并获取当前时刻，使比较来自同一次受锁保护的观察。
- 采样线程也在拿到状态锁后重新读当前时刻，避免 Prepare 在等待锁期间设定新时间，采样却拿旧时刻进入状态机。
- 保留 250 ms 的采样／绘图超时保护；真实停滞、时钟异常、HOME、休眠和应用切换仍会停止输入。不增加运行时内存池额度，不延长活动时限。
- 多项检查同时异常时保留首个停止原因，不用旧 mode 继续覆盖。
- 新增自动停止原因、采样间隔、触摸年龄和两条心跳年龄日志。只记录停止转换，不逐帧落盘；发送线程先发送中立状态再写日志，同一连续控制器错误不重复刷屏。

日志名称：`sampler-stop-reason`、`watchdog-stop-reason`、`sampler-stop-period-ms`、`sampler-stop-touch-age-ms`、`watchdog-sample-age-ms`、`watchdog-render-age-ms`、`injector-error`。

主要 reason 编号：2=HOME、3=Sleep、4=Tesla、5=Application changed、6=Stale touch、7=Timeout、8=Invalid input、9=Controller error、10=Display error、13=Docked、14=Clock gap。用户界面继续显示文字原因。完整枚举在 common/protocol.hpp。

## 验证

新增回归测试复现“服务等待期间生产者发布新心跳”的交错，并模拟 120 秒持续 A 键输入，确认新检查不误停用。测试同时保留真实 250 ms 停滞释放输入、暂停后不自动恢复、绘图超时和首个原因优先级检查。模拟时间不是实机持续运行成绩。原有触摸、异步通信及显示栈切换测试继续执行。

安装后完整重启，确认 Touchpad 标题为 rc9。在已验证可用的游戏内启用，连续操作约 2 分钟，再检查松手释放和 HOME／Tesla 暂停。若再次自行消失，在重新启用前记下菜单底部提示；新日志可进一步区分真实停滞、触摸采样中断或其他停用原因。后台仍须手动启动，未启用 boot2.flag。
