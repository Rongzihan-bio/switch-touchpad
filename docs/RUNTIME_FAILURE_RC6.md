# rc6：启动成功后的 Tesla／输入异常

2026-09-24，用户反馈，尚未读回本次 SD 日志：

- Diag A 的 Launch 返回全零，Tesla 手动启动也曾显示成功。
- 在应用模式 hbmenu 打开 Touchpad Input Test 后，Tesla 显示“显示层：已就绪”“错误码：00000000”。
- “未连接”明确位于“虚拟手柄”一行，不是顶部后台状态，也不是 IPC 错误提示。尚未启用时，此项未连接符合代码的设计。
- 用户再次确认，触发异常的按钮文字是“启动后台（本次开机）”。之后 Tesla 消失，测试程序无法使用实体手柄输入，也没有虚拟控件。
- HOME 仍响应，Tesla 唤出组合键不响应。不能称为整机完全失去响应。

## 源码核查

`overlay/main.cpp` 的 launchBackend 在 online 为真时只更新“后台已经运行”文字并返回，按钮本身不调用 hide。调用 hide 的启用／配对路径与这个按钮不同。保留用户确认的操作，不擅自把反馈改写为点击了“启用”。必须通过实际文件与运行记录解释差异。

Tesla UI 线程中存在同步后台 IPC 和 PM 启动调用；libtesla 也在主循环中执行清屏及输入权限恢复。阻塞、异常退出或权限恢复失败是待查方向，尚未确定实际阻塞在哪一步。当前库的 requestForeground 忽略系统调用返回码，已有 startup.log 只记录后台初始化，不记录 Tesla 按钮和焦点恢复，不能预设现有日志就一定能证明根因。

另外，overlay 在通信失败时设置 online=false，却仍用上一次 status 显示显示层和后台错误码；这些显示不应脱离通信状态单独作为健康判断。本次用户所说的“未连接”不是这一情况的证据。

rc6 后台的单缓冲及无期限 dequeue 也需要运行时排查，但 libnx 本身允许单缓冲，不能仅凭此配置断言本次故障原因。没有为这些假设发布试错版本。

若现有记录不足，再针对按钮入口、同步调用前后、隐藏原因和输入权限恢复返回值加入日志，以缩小下一次验证范围。保持 Applet 配置和手动启动，不能因 Launch 返回零就记录为完整输入链路通过。
